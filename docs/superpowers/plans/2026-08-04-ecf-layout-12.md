# ECF leiaute 12 read-only Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar `TecnoFisc.Sped.Ecf` read-only com modelo tipado único do leiaute 12, leitura compatível dos leiautes 8 a 12 e cobertura integral dos 180 registros dos 17 blocos.

**Architecture:** Um tooling Python isolado e executado explicitamente converte o manual oficial em Markdown por página, aplica reparos determinísticos, fragmenta os 180 registros e promove atomicamente um manifesto revisável. O pacote .NET segue o desenho do ECD (`ParserEcf`, `ArquivoEcf`, `BlocoEcf`, catálogo source-generated), usando `IntroduzidoEm` e `DesdeVersao` para representar os deltas oficiais dos leiautes 8 a 12 sem criar classes por versão. O manifesto orienta e verifica a implementação, mas cada lote só fecha após revisão das páginas renderizadas do manual.

**Tech Stack:** .NET 10, C# 14, xUnit v3, FluentAssertions, `TecnoFisc.Sped.Core`, `TecnoFisc.Sped.Txt.Engine`, source generator TXT existente, Python 3.11+, `uv`, `pymupdf4llm==1.28.0`, PyMuPDF e JSON Schema Draft 2020-12.

## Global Constraints

- Pacote read-only: parser e modelo tipado; não criar `GeradorEcf`, pasta `Gerador/` ou API pública de escrita.
- Modelo público único do leiaute 12; não criar tipos `RegistroXxxxVYYY`.
- Aceitar somente leiautes `V008`, `V009`, `V010`, `V011` e `V012`, declarados por `Registro0000.CodVer`.
- Reconhecer exatamente 180 registros dos blocos, nesta ordem: `0 -> C -> E -> J -> K -> L -> M -> N -> P -> Q -> T -> U -> V -> W -> X -> Y -> 9`.
- Fonte normativa do baseline: `sped/guides/Manual_ECF_Leiaute_12_29_01_2026.pdf`, ADE Cofis nº 02/2026, atualização janeiro/2026.
- Manuais oficiais ou históricos dos leiautes 8 a 11 são obrigatórios antes de fechar a compatibilidade de cada versão; fixtures reais são evidência, não especificação.
- Runtime do pacote referencia somente `TecnoFisc.Sped.Core` e `TecnoFisc.Sped.Txt.Engine`; o source generator entra apenas como analyzer com `ReferenceOutputAssembly="false"`.
- O tooling em `tools/ecf-layout/` não entra em `dotnet build`, `dotnet test`, `dotnet pack` nem no runtime.
- Cache, Markdown integral, fragmentos locais, relatórios de quarentena, páginas renderizadas, fontes privadas e hashes das fontes ficam fora do Git.
- Versionar apenas `sped/ecf/layout-12-manifest.json`, seu schema, `sped/STAGE_17_ECF_BASELINE.md` e fixtures anonimizadas compactas.
- Validar formato e hierarquia sintática; não implementar `REGRA_*`, cálculos de IRPJ/CSLL, reconciliações ou obrigatoriedade tributária condicional.
- Tabelas dinâmicas extensas, parametrizadas ou mutáveis permanecem `string`; somente códigos pequenos e estáveis, confirmados no manual/histórico, viram enum.
- Encoding dos arquivos ECF: Latin1/Windows-1252; I/O assíncrono propaga `CancellationToken`; `ReadStreamingAsync` é o caminho recomendado.
- Cada lote termina com build sem warnings, testes focados, comparação manifesto/catálogo, tracker atualizado, inspeção da página normativa e Conventional Commit válido.
- Nenhuma fixture, log, mensagem de teste ou caminho versionado pode conter nome empresarial, identificador ou caminho privado.
- A promoção para `TecnoFisc.Sped.Txt` e `TecnoFisc.Sped` ocorre somente no gate final de 180/180 registros.

## Contrato dos lotes de registros

O comando de scaffold consome somente entradas já marcadas `reviewed: true` no manifesto. `--tests-only` cria contratos data-driven que falham enquanto o catálogo não contém os códigos; `--source` cria drafts conservadores, nunca enums fiscais automaticamente. Em cada registro, a revisão humana aplica estas regras exatas:

```text
Data com formato explícito ddMMyyyy/MMyyyy -> DateOnly + CampoSped.Formato
Quantidade/valor com casas decimais       -> decimal
Inteiro de contagem                        -> int (long se tamanho > 9)
CNPJ/CPF                                   -> Cnpj/Cpf do Core
Código numérico com zero significativo     -> string
Domínio fechado pequeno e estável          -> enum ECF após conferir manual/histórico/tabelas
Domínio grande, parametrizado ou mutável    -> string
Mudança incompatível entre V008..V012       -> string que preserve todas as representações
REGRA_*                                     -> comentário XML apenas quando necessário ao uso
```

Cada tarefa de lote traz sua lista literal para os comandos `--tests-only --codes` e `--source --codes`. O primeiro teste deve falhar informando os códigos ausentes; depois da implementação deve passar. Antes do commit, montar/atualizar a fixture `Fixtures/Sinteticas/bloco-{identificador}.txt` declarada na própria task, executar o teste do bloco quando ele ficar completo, marcar no tracker somente as linhas realmente revisadas e rodar `git diff --check`.
